# v0.3: Publication Dates and Multilingual Content Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Claude can set publication dates on any status, and it can create linked, same-design translations of pages and posts on sites using Polylang or WPML.

**Architecture:**
- **Dates.** They extend `PostSupport::plan` and `PostFormatter::summary`.
- **Multilingual.** A `WPDM\I18n\Languages` adapter, with Polylang and WPML implementations, hides the language plugin. On top of it sit:
  - a pure `WPDM\I18n\Segments` engine that extracts translatable strings from content and splices translations back in place, protecting script, style and shortcodes with markers;
  - six MCP tools under `includes/Tools/I18n/`, registered only when a language plugin is active.

**Tech Stack:** PHP 7.4+, WordPress 6.2+ (tests on 7.1.5 and 6.8), Polylang (free, real in tests), WPML (documented hooks only, test double), Yoast via `WPDM\Seo\Yoast`.

**Spec:**
- `docs/superpowers/specs/2026-11-24-post-dates-design.md`
- `docs/superpowers/specs/2026-11-24-multilingual-design.md` (approved; "(call)" marks the builder-check rulings)

## Global Constraints

- The translation is always created as `draft`. The source post, the library items and existing translations are never modified.
- If the source already has a translation in the target language, the result is `conflict` with `{existing_id}`.
- Language codes are the language plugin's own codes. An unknown code gives `invalid_argument`, with the valid codes listed.
- Markers have the form `⟦n⟧` (U+27E6, n, U+27E7) and are numbered from 1 per segment, in document order.
- Protected parts are `<script…>…</script>`, `<style…>…</style>`, `[shortcode …]` / `[/shortcode]`, `<!-- … -->` and `<?php … ?>`.
- `divi/code` and every `html` segment use the protected-part rule. A segment that loses a marker, or changes its sequence of tag names, falls back to the source text and adds a warning.
- Never-prose keys: `src`, `linkUrl`, `url`, `id`, `width`, `height`, `sizes`, `srcset`, `icon`, `linkTarget`. Object prose keys: `text`, `title`, `alt`, `caption`, `label`, `placeholder`, `titleText`.
- Legacy Divi 4 content (it contains `[et_pb_`) gives `invalid_argument` with "convert the page to Divi 5 first".
- Do not touch the server instructions (1498/1500 characters).
- PHP 7.4 compatible.

## Review Focus

- **A responsive `tablet` or `phone` value that equals `desktop`** gets the desktop translation. One that differs is its own segment. Pinned in Task 4 (`test_responsive_variants`).
- **A segment where Claude dropped a marker or a `</td>`** keeps the source text, adds a warning, and the page still saves. Pinned in Task 4 (`test_broken_segment_falls_back`).
- **The source page edited between extract and create** gives `conflict`, and nothing is created. Pinned in Task 5 (`test_create_conflicts_when_source_changed`).
- **Two global-layout blocks with the same library id in one page** create one translated library item, and both blocks use it. Pinned in Task 5 (`test_same_global_module_twice_creates_one`).
- **A post type that is not translatable in the language plugin** gives `invalid_argument` on extract, create and set_language. Pinned in Task 3 (`test_untranslatable_type_rejected`).

### Task 4: Segments engine (pure)

**Files:**
- Create: `includes/I18n/Protect.php`
- Create: `includes/I18n/Segments.php`
- Test: `tests/Unit/I18n/ProtectTest.php`, `tests/Unit/I18n/SegmentsTest.php` (no language plugin needed). Use fixtures cut from `plantilla5-19.json` and `homepage 2026.json` into `tests/fixtures/i18n/`, holding only the needed blocks and no client text beyond what is already in the repo's golden fixtures.

**Interfaces:**
- `Protect::mask( string $html ): array{text:string, parts:string[]}` replaces the protected parts with `⟦1⟧…⟦n⟧`.
- `Protect::unmask( string $text, array $parts ): ?string` returns null if any marker is missing or duplicated.
- `Protect::tags( string $html ): string[]` gives the sequence of tag names, open and close (e.g. `['div','p','/p','/div']`). It runs on masked text.
- `Segments::extract( string $content ): array{segments: array<int,{id,kind,context,text}>, globals: array<string,int[]>, code_blocks: int, legacy: bool}`:
  - `globals` maps each library id string to the block indexes that use it;
  - `text` of `html` segments is masked;
  - `legacy` is true when the content contains `[et_pb_`.
- `Segments::apply( string $content, array $translations, array $global_map = [], ?callable $link_map = null ): array{content:string, fallbacks:string[], unknown:string[]}`:
  - `$translations` maps segment id to text;
  - `$global_map` maps a source library id string to `[target_id_string, target_content]`;
  - `$link_map` is `fn(string $url): ?string`. It is applied to `href` values inside translated `html` segments and to `linkUrl` / `url` attrs.
  - `$post_map` is `fn(int $id): ?int`. It is applied to the `post_id` inside `$variable(...)$` dynamic links. A null result keeps the original.

  Signature: `apply( string $content, array $translations, array $global_map = [], ?callable $link_map = null, ?callable $post_map = null )`.
- Segment ids as in the spec:
  - `b<n>.<attr.path>`, where `n` counts the opening and void `divi/*` blocks outside global-layout children, from 0;
  - `gb<n>` for core blocks (inner HTML);
  - `c` for classic content.

  The title, excerpt and SEO segments are added by Task 5, not here.
