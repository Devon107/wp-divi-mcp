# Claude Desktop extension (.mcpb) per connection — design

Date: 2026-11-23. Status: approved by the owner.

## Why

claude.ai and Claude Desktop "custom connectors" reach the site from Anthropic's cloud. During sign-in discovery they identify as `python-httpx`, and WP Engine's edge returns 403 to any User-Agent starting with `python-…` on the whole site. Neither "Continue anyway" nor WP Engine Web Rules get past it (tested by the owner on immedexdev; Web Rules cannot rewrite request headers). A local MCP server inside Claude Desktop connects from the user's own computer, so it never meets that block. The owner wants this to work for them and for other people who install the plugin on their own sites, with no host tickets and no third-party relays.

## Goals

- Settings → Divi MCP offers a one-click "Download for Claude Desktop" file for a new connection.
- Several sites can be installed side by side in one Claude Desktop.
- Works on WP Engine and on any other host. No external service.
- Works on Claude Desktop for macOS and Windows. Linux (owner runs Desktop 6.28899.6) is to be verified by the owner.

## Non-goals

- No change to the remote HTTP endpoint, auth or tools.
- No claude.ai web or mobile support on WP Engine (impossible without the host).
- No OAuth.

## Anti-goals

- The key must not end up in a URL, a log or a long-lived server-side store.
- No npm dependencies in the bundle.

## Approaches

1. **One .mcpb per connection, generated by the plugin (chosen).** Unique extension name per site, URL with key embedded. Supports many sites.
2. One generic .mcpb that asks for the URL at install (`user_config`, sensitive). Rejected: Claude Desktop identifies extensions by name and will not install the same one twice, so only one site per computer.
3. Tell users to run `npx mcp-remote`. Rejected: needs a terminal and Node setup.

## Design

- **Proxy** `assets/mcpb/server.js`: Node, no dependencies (global `fetch`, Node 18+, shipped with Claude Desktop). It reads newline-delimited JSON-RPC from stdin and POSTs each message to `WPDM_URL` with `Content-Type: application/json`, `Accept: application/json, text/event-stream` and `User-Agent: wp-divi-mcp-desktop/<version>`. It stores the `Mcp-Session-Id` from responses and sends it on later requests. 200 bodies (object or batch array) are written to stdout one line each; 202 writes nothing. On HTTP or network errors, any request that had an id gets a JSON-RPC error response, so Claude never hangs. On stdin end it sends DELETE for the session (best effort) and exits. Logs go to stderr only, and never include the URL.
- **Builder** `includes/Admin/Mcpb.php`: `Mcpb::build( string $url, string $label ): string` returns the zip bytes, using ZipArchive in memory (temp file). Contents:
  - `manifest.json` (manifest_version "0.3"): name `wp-divi-mcp-<site-host-slug>-<label-slug>`, display_name "Divi MCP – <label> (<host>)", version = plugin version, description, author, `server: {type: "node", entry_point: "server/index.js", mcp_config: {command: "node", args: ["${__dirname}/server/index.js"], env: {WPDM_URL: <url>}}}`, `compatibility.platforms: ["darwin","win32","linux"]`.
  - `server/index.js`: a copy of `assets/mcpb/server.js`.
- **Settings page**: the shown-once box gets a "Claude Desktop" row with a "Download for Claude Desktop" link. The link is a `data:application/zip;base64,…` URI with a `download="<slug>.mcpb"` attribute, built during that single render. The token is never stored again and needs no second request. A note says to treat the file like the URL, and to revoke the connection if it leaks. When ZipArchive is missing, the row shows a short notice instead of the link.
- **Docs**: `docs/connect.md` gets a Claude Desktop section (download, double-click, enable, and the WP Engine note).
- **Tests**:
  - PHP (WP suite): the zip has the two entries, the manifest is valid JSON with the expected fields, unique names per label and host, the URL in env, and the server copy matches the asset.
  - Node (`node --test`, run in CI): against a fake HTTP server, covering initialize with session capture, a follow-up call carrying the header, a 202 notification, a batch, an HTTP 401 mapped to an error, and DELETE on close.
- **Ships**: `assets/` is already in the zip. The Node test goes in `tests/` (excluded from the zip).

## Left to the builder

- Exact manifest description text and the icon (none for now).
- Slug length limits: keep the name at 64 characters or fewer.
